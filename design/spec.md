# 純草稿・自動結算 Roguelike 卡組構築：Gate 2 規格

狀態：Gate 2 decision required（Balance 未通過）  
日期：2026-07-28  
Scope：small

## 一句話

讀懂敵人的公開攻擊腳本，把四張條件指令排成優先序，然後承擔一次提交、全程不可介入的決定性戰鬥結果。

## 核心循環（三句話）

1. 玩家先看下一場敵人的生命、逐回合攻擊值與特殊事件，並從本 run 收集的指令中選四張排成優先序。
2. 按下「提交誓約」後，戰鬥依 seed、敵方腳本與四張指令逐 tick 自動結算；玩家只能觀看，不能補牌或改指令。
3. 勝利後從三張新指令中選一張，再決定路線；失敗即結束 run，下一局重新草稿。

## 產品定位與 pivot

原提案的「瀏覽器純草稿 autobattler 是市場空白」已被 Siegelock 反駁，詳見 `competition-audit.md`。本作保留小型、可模擬、戰鬥零輸入的選題，但把記憶點收斂到：

- 敵方未來事件完全公開，不靠隱藏資訊製造難度。
- 玩家不是逐張出牌，而是編譯一份四格條件腳本。
- 同一事件最多觸發一張指令，槽位順序就是優先權。
- 戰後時間線能說明每一點傷害、護盾與觸發來源。
- 同 seed、同腳本必須逐 tick 得到相同結果。

## 玩家承諾

- 第一次有意義的腳本排序選擇在開始後 30 秒內出現。
- 每場準備 30–75 秒，自動戰鬥 10–20 秒。
- 完整 run 7 場，目標 15–20 分鐘。
- 輸掉時能指出「哪個公開事件讀錯」或「哪個優先序造成錯過觸發」，而不是只怪隨機。

## 戰鬥規則

### 狀態

- 玩家有 20 點 `resolve`，跨遭遇保留。
- 敵人有公開生命值與最多 6 回合的攻擊腳本。
- 玩家每回合固定造成 3 點基礎傷害。
- `guard` 先吸收傷害，遭遇結束後歸零。
- 每場最多 6 回合；未擊敗敵人視為失敗。

### 四格誓約腳本

玩家從收藏選四張不同指令，放入槽位 1–4。當事件發生時，由左至右找第一張「條件符合且仍有 charge」的指令觸發；該事件不再檢查後續指令。

第一版事件只有五種：

- `opening`：戰鬥開始。
- `round_start`：每回合開始。
- `after_hit`：玩家的生命實際受到傷害後。
- `self_below_half`：本場首次觀察到玩家生命位於一半以下；低血進場也會在 opening 後產生一次。
- `enemy_below_half`：敵人生命首次降至一半以下。

每張指令預設每戰 1 charge。任何效果不得直接製造同類事件；這是防止遞迴觸發與軟鎖的硬規則。

### 結算順序

1. 觸發 `opening`。
2. 回合開始，觸發 `round_start`。
3. 玩家造成 3 點基礎傷害。
4. 若首次跨過敵人半血，觸發 `enemy_below_half`。
5. 敵人依公開腳本攻擊，先扣 guard，再扣 resolve。
6. 若生命實際受損，觸發 `after_hit`；若首次跨過半血，再觸發 `self_below_half`。
7. 任一方生命歸零即結束；否則進下一回合。

## Run 結構

```text
起始四張指令
  → 普通戰 → 草稿
  → 普通戰 → 草稿
  → 精英戰 → 草稿 + 回復 3
  → 普通戰 → 草稿
  → 精英戰 → 草稿 + 回復 3
  → 守門戰 → 草稿
  → Boss
```

- 起始收藏固定四張，確保第一戰可教學。
- 每次草稿從尚未擁有的指令中提供三張，由 seed 決定。
- 玩家可收集超过四張，但每戰只能帶四張，不能刪牌。
- 第 3、5 戰後固定回復 3 點，將持久生命變成路線壓力，而非單場二元判定。
- 首版沒有永久數值成長。Meta 只解鎖敵人檔案、seed 歷史與外觀，避免早期平衡被帳號進度污染。

## 指令設計原則

每張指令必須改變排序、觸發窗口或風險承擔，不能只寫「攻擊 +1」。

| 軸 | 玩家問題 | 範例 |
|---|---|---|
| 時機 | 我要搶開場，還是留到半血？ | 先聲、終局證明 |
| 防守轉換 | 我承受一次傷害，換取什麼？ | 鏡像債務、石牆協議 |
| 門檻 | 我要刻意壓低自己／敵人的生命嗎？ | 紅線條款、慈悲迴路 |
| 優先權 | 同事件兩張牌，哪張先消耗？ | 每回合類指令競爭 |
| 敵方反制 | 這場公開腳本要求我換掉哪張常用牌？ | 封印條款、延遲引信 |

首版內容上限：

- 12 張玩家指令。
- 7 個敵人模板（4 普通、2 精英、1 Boss）。
- 3 種公開修正：重擊、連擊、封印。
- 不做職業、裝備、地圖事件、商店或卡牌升級。

## 初始數值與來源

這些不是平衡結論，而是供紙上原型否決的起點。

| 數值 | 初始值 | 設計意圖 |
|---|---:|---|
| 玩家 resolve | 20 | 容許前兩戰各承受約 4–6 傷害，仍讓持久傷害有壓力 |
| 基礎傷害 | 3／回合 | 沒有指令也能在 6 回合造成 18，讓兩攻兩防的保守腳本仍有數學上的 Boss 勝法 |
| 腳本槽位 | 4 | 手機／瀏覽器一屏可讀，且 4! = 24 種排序足以形成小型解謎 |
| 每戰回合上限 | 6 | 自動播放可壓在 20 秒內，並限制觸發鏈長度 |
| 指令 charge | 1 | 從結構上排除無限循環 |
| 普通敵人生命 | 13–20 | 需要 1–2 張傷害指令配合基礎攻擊 |
| Boss 生命 | 32 | 要求完整 build，但仍能在 6 回合內解決 |

所有數值在 Gate 2 前由 `sim/prototype.ts` 跑至少 20,000 局。通過後仍只代表可行，不代表好玩。

## Balance 驗收門檻

- 混合策略總勝率：25–40%。
- 四種基準策略中，最高與最低勝率差不得超過 18 個百分點。
- 任一 build signature 不得占全部勝場超过 30%。
- 12 張指令中，任一張在勝場 loadout 的出現率不得低於 2%。
- 前五名最常見完整 loadout 合計不得超过全部勝場的 45%。
- 相同 seed 與策略重跑，完整摘要必須相同。
- 20,000 runs 在開發機執行時間目標低於 3 秒。

若無法同時達成，最多修訂兩輪；第三輪仍失敗則回 Studio Head 決定 pivot 或停止。

## 資訊設計

準備畫面必須同時呈現：

- 敵方每回合攻擊值與特殊事件。
- 預估最早／最晚可能結束回合；不得直接顯示勝敗答案。
- 四格腳本與每張牌會監聽的事件。
- 目前 resolve、預期最壞承傷與可能浪費的 trigger。

戰鬥畫面必須呈現：

- 目前 tick 與來源。
- 哪張指令因優先權觸發。
- 哪張符合條件但因同事件已被前位指令消耗而沒有觸發。
- seed 與「複製重播碼」。

## 失敗條件與停止規則

Gate 2 應否決本設計，如果：

- 模擬只靠一種高傷排序才能過關。
- 防守牌只是在延長必敗戰鬥，無法創造跨遭遇價值。
- 改變敵方腳本後，最佳四張與排序幾乎不變。
- 人類閱讀四張條件後仍無法在 75 秒內做出有理由的排序。
- 「條件腳本」在視覺與操作上仍被感知成另一款一般 autobattler。

## Gate 2 決策題

1. 「公開敵方腳本＋四格條件優先序」是否足以取代已失效的市場空白主張？
2. 15–20 分鐘、7 戰的 run 是否適合首款作品集 scope？
3. 是否接受第一版不做永久數值成長、商店與卡牌升級？

## Balance 結果

20,000 局同 seed 第二輪結果未達 Gate 2 門檻：總勝率 11.43%，四種策略勝率落差 39.03 個百分點，前五組勝場 build 佔 82.32%，且仍有三張指令低於 2% 勝場出現率。

這不是再調 1–2 點數值能修正的問題。四個一次性槽位中至少三格必須提供傷害，否則 6 回合內無法通過後段敵人；因此「自由編排條件腳本」實際收斂成「三攻一功能」。詳見 `sim/reports/2026-07-28-gate-2-feasibility.md`。

Designer 與 Balance Engineer 均不建議以本規格進入 Gameplay Engineering。
