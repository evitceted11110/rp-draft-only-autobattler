# 視覺規範：午夜契約終端

## 核心語彙

畫面是一座「會發光的契約編譯器」，不是中古卡桌。玩家操作的是四格條件腳本，所有視覺都服務於「讀取 → 排序 → 提交 → 追溯結果」。

## 色彩

- 背景：色相 218–230°、飽和度不超過 28%、亮度不超過 12%。
- 面板：比背景亮 4–8%，以 1px 半透明邊線區隔，不用厚重陰影。
- 主要互動：青綠 `#6de4c1`。
- 危險與敵方：珊瑚紅 `#ff786f`。
- 稀有／條件事件：琥珀 `#f4c95d`。
- 文字：主文 `#eef4f2`，次文 `#91a5a0`；正文對比至少 4.5:1。

## 形狀

- 指令卡左上角用切角，代表可編排的機器語句。
- 事件以膠囊標籤呈現；同事件必須使用同色與同名，不能只靠圖示。
- 四個槽位以垂直編號線連接，讓優先序在縮圖中仍可辨識。
- 敵方攻擊腳本使用等寬數字格，不畫擬真角色。

## 戰鬥表演

- 戰鬥畫面固定呈現三層：左側四格指令佇列、中央玩家與敵方舞台、右側公開攻擊腳本。
- 每個 deterministic timeline entry 必須映射成至少一個非文字訊號：攻擊投射物、受擊震動、護盾展開、治療光暈、充能旋轉或契約結果。
- 目前觸發的指令必須在左側佇列高亮；目前敵方回合必須在右側腳本高亮。
- 玩家 resolve、guard 與敵方 integrity 同時使用數字與狀態條，不得只靠顏色或動畫。
- 文字追溯保留為輔助與事後檢查，不再是理解戰鬥的唯一媒介。

## 詞條與構築語言

- 每張詞條卡固定以「觸發圖示 → 效果圖示 → 精確數值」表達，不要求玩家先讀完整句子。
- 同一效果在整備卡、構築預演、戰鬥佇列與戰鬥特效中使用相同圖示與顏色：直擊紅、修復青、護盾琥珀、強化紫。
- 整備畫面必須根據目前敵人跑一次 deterministic 預演，顯示流派名稱、每張詞條的預期觸發回合、未觸發詞條及戰後雙方剩餘值。
- 每個戰鬥 tick 的中央特效牌必須同時回答三件事：來源是誰、發生什麼效果、數值改變多少。
- 特效只負責建立因果與節奏；傷害、治療、護盾、強化的精確數值必須保留到動畫結束後仍可讀。

## 單畫面 HUD

- 桌面基準尺寸為 `1280 × 720`；準備、戰鬥、戰後草稿三個主要狀態各自必須完整容納於 `100dvh`。
- 文件本身不得垂直或水平滾動；驗收時 `document.documentElement.scrollHeight` 必須等於 `clientHeight`。
- 提交、暫停／加速／跳過、草稿選擇等主要操作不得落在 viewport 之外，也不得藏入 hover 才能發現。
- 優先壓縮裝飾與重複說明，再壓縮字級；不以巢狀滾動區取代頁面滾動。

## 動態

- 拖放以 140–180ms 位移完成，不使用彈簧過衝。
- 戰鬥時間線逐筆揭露；一般速度每筆約 760ms、快速模式約 380ms，並提供暫停與跳過。
- 觸發卡只做一次 2px 外框脈衝；生命與護盾改變不得只靠動畫，必須同步顯示數字。
- 尊重 `prefers-reduced-motion`，停用位移與脈衝後仍保留完整資訊。

## 程式化限制

- 不載入外部圖片、影片或圖示字型。
- 所有裝飾由 CSS 漸層、邊框與文字產生。
- 遊戲邏輯不得依賴任何視覺 token。

## 語言

- 所有玩家可見文字使用繁體中文，包括資源、回合、階級、模式、結算與無障礙標籤。
- 程式內部識別字可以保留英文，但不得直接以 `toUpperCase()` 等方式顯示在介面。
- 必須翻譯遊戲術語，不混用 `RESOLVE`／決心、`GUARD`／護盾等兩套名稱。
- 版本檢查應掃描渲染模板與核心戰鬥訊息，確認沒有意外漏出的英文常數。
