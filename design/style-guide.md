# 視覺規範：午夜契約終端

## 核心語彙

畫面是一座「會發光的契約編譯器」，不是中古卡桌。玩家操作的是四格條件腳本，所有視覺都服務於「讀取 → 排序 → 提交 → 追溯結果」。

## 色彩

- 背景：色相 218–230°、飽和度不超過 28%、亮度不超過 12%。
- 面板：比背景亮 4–8%，以 1px 半透明邊線區隔，不用厚重陰影。
- 主要互動：青綠 `#6de4c1`。
- 危險與敵方：珊瑚紅 `#ff786f`。
- 稀有／條件事件：琥珀 `#f4c95d`。
- 文字：主文 `#eef4f2`，次文 `#91a5a0`；正文對比至少 4.5:1。

## 形狀

- 指令卡左上角用切角，代表可編排的機器語句。
- 事件以膠囊標籤呈現；同事件必須使用同色與同名，不能只靠圖示。
- 四個槽位以垂直編號線連接，讓優先序在縮圖中仍可辨識。
- 敵方攻擊腳本使用等寬數字格，不畫擬真角色。

## 戰鬥表演

- 戰鬥畫面固定呈現三層：左側四格指令佇列、中央玩家與敵方舞台、右側公開攻擊腳本。
- 每個 deterministic timeline entry 必須映射成至少一個非文字訊號：攻擊投射物、受擊震動、護盾展開、治療光暈、充能旋轉或契約結果。
- 目前觸發的指令必須在左側佇列高亮；目前敵方回合必須在右側腳本高亮。
- 玩家 resolve、guard 與敵方 integrity 同時使用數字與狀態條，不得只靠顏色或動畫。
- 文字追溯保留為輔助與事後檢查，不再是理解戰鬥的唯一媒介。

## 動態

- 拖放以 140–180ms 位移完成，不使用彈簧過衝。
- 戰鬥時間線逐筆揭露；一般速度每筆約 760ms、快速模式約 380ms，並提供暫停與跳過。
- 觸發卡只做一次 2px 外框脈衝；生命與護盾改變不得只靠動畫，必須同步顯示數字。
- 尊重 `prefers-reduced-motion`，停用位移與脈衝後仍保留完整資訊。

## 程式化限制

- 不載入外部圖片、影片或圖示字型。
- 所有裝飾由 CSS 漸層、邊框與文字產生。
- 遊戲邏輯不得依賴任何視覺 token。
